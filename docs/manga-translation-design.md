## 0. 阅读指引

### 0.1 定位

本文是**决策记录 + 实施契约**，不是需求 brainstorm。26 条交互与结构决策已由产品侧确认（见第 10 章），本文把它们翻译成可执行的工程约束；原 4 项待确认已在 11.3 关闭，当前无阻塞项。

### 0.2 与全自动方案的关键差异

参考仓库 Fushi 走的是「整页自动 OCR → 原文 → 点字查词典 → 制卡」，其中约 9600 行 Dart 用在**替代人眼判断版面**（阅读序、行布局、字形框、去振假名）。本方案把这件事交还用户（人工框选），因此整段砍掉：

- 文本检测模型（RT-DETR 一类）不需要
- 阅读序推导不需要
- 逐字命中几何不需要
- 译文覆盖层排版不需要
- 整卷调度与 `manga.json` 数据契约不需要

代价是交互摩擦从机器转移到人，且 OCR 质量开始依赖用户框得准不准（详见第 8.5 节“框内分列”）。

## 1. 结论摘要

**一句话**：在阅读页加一个「框选 → 识别 → 翻译」的轻量通路，状态纯内存、五页封顶、用完即丢；渲染层做三套适配，OCR 与翻译各自独立成层。

五个关键取舍：

1. **只接识别模型，不接检测模型**——用户框选替代检测，包体从数十 MB 降到 4.5–21 MB。
2. **译文面板参与布局，不叠在漫画上**——面板出现时挤压内容区，三种阅读形态三套布局。
3. **OCR 本地、翻译联网**——本地模型按需下载（内建预设，不开放导入），翻译默认零配置（Edge 端点）+ 可选 key（Azure / LLM）。
4. **存储粒度 page、聚合粒度 spread**——绕开双页 spread 组合动态变化导致的坐标失效。
5. **不做持久化**——不跨章节、退出即丢；仅用 `SavedStateHandle` 兜住“切后台被回收”。

另一条结构性约束：**阅读页只放功能，参数全部收在 `设置 → 翻译`**，首次因配置不全而点按钮时直接跳设置，配完返回自动续开（见 4.6–4.9）。

规模量级（供排期参考，不含 OCR 质量调优）：新增 1 个模块 + 3 处渲染栈适配 + 面板与状态机 + 两个服务层，四个阶段可独立验收。

## 3. 用户流程与状态机

### 3.1 主流程

```
点「翻译」按钮
  → 配置不完整（模型/引擎/同意）？→ 跳「设置 → 翻译」，配完返回自动续开（见 4.8）
  → 面板出现在预留区域（底栏隐藏、页码上移）
  → 进入绘制态（翻页点击区禁用、单指拖动用于画框）
  → 手指拖动出矩形 → 抬起
      → 生成条目：编号 n、状态 ocr
      → 裁切 → 分列 → 识别（串行队列）
      → 识别完成 → 状态 mt → 提交翻译
      → 翻译完成 → 状态 ready，面板中追加一条
  → 继续画下一个框（编号 +1）
  → 手动关闭面板 → 退出翻译态，清空会话
```

### 3.2 条目七态

| 状态         | 含义        | 面板表现             | 可进入自                 |
| ---------- | --------- | ---------------- | -------------------- |
| `draft`    | 手指拖动中     | 虚线框 + 实时尺寸       | —                    |
| `ocr`      | 裁切/分列/识别中 | 编号徽标转圈           | `draft`              |
| `mt`       | 翻译请求中     | 显示原文 + 译文占位      | `ocr` / `editing`    |
| `ready`    | 有译文       | 译文 + 浅色原文单行      | `mt`                 |
| `expanded` | 原文展开全文    | 译文 + 原文多行        | `ready`              |
| `editing`  | 编辑原文      | 输入框 + 键盘         | `ready` / `expanded` |
| `failed`   | 翻译失败      | 原文 + “翻译失败，点按重试” | `mt`                 |

删除是终态：`ocr` 中删除须**取消在途任务**；其余状态直接移除并**重排编号**。

### 3.3 未定义转移的处置

| 场景                 | 处置                      |
| ------------------ | ----------------------- |
| 识别中删除条目            | 取消 Job，丢弃结果，编号重排        |
| 编辑中翻页/切章           | **禁止**（编辑态锁翻页，与绘制态同一把锁） |
| 编辑中触发五页淘汰          | 同上，被锁挡住                 |
| 条目所属页被淘汰           | 无法到达（淘汰时条目一并丢弃）         |
| 翻译失败后用户再次点按        | 重新提交该条（走 `failed → mt`） |
| 跨页条目在 spread 重组后失效 | 降级为两条独立条目并提示一次（见 5.5）   |

## 4. 界面与布局

### 4.1 三种形态

| 形态   | 面板位置 | 尺寸规则                  | 内容区变化                                                    |
| ---- | ---- | --------------------- | -------------------------------------------------------- |
| 竖屏单页 | 底部   | 高 = 屏高 30% 默认，可拖至 45% | 高度减去面板高，图片在剩余区域内居中（视觉上移）                                 |
| 横屏双页 | 右侧   | 宽 = 屏宽 30% 上限，默认 25%  | 宽度减去面板宽，图片左缩居中                                           |
| 条漫竖屏 | 底部   | 同竖屏单页                 | RecyclerView 加 `paddingBottom` + `clipToPadding = false` |

横屏面板宽度建议再夹一层绝对值：`clamp(240dp, 30% 屏宽, 360dp)`，否则平板上面板会被拉成一条长条，译文行长不可读。【建议值，待确认】

### 4.2 “不覆盖漫画”的精确含义

**只吃留白，留白不够才缩图。** 设容器高 `Hc`、图片实际显示高 `Hi`、下留白 `B = (Hc - Hi) / 2`、面板高 `P`：

- `P ≤ B`：图片**不动**，面板完全落在原本的留白里；
- `P > B`：内容区高 = `Hc - P`，图片重新 `CENTER_INSIDE`。

不按这条算，每加一条译文、每翻一页，图片大小都会变，阅读时画面持续抖动。

### 4.3 拖拽拉伸

- 拖动中**只改面板视觉**（位移 + 半透明 + 阴影），不触发布局重排；松手后 200ms 动画让位。
- 重排基准是**原始 fit 尺寸**，不是上一次结果——否则多次拖拽会累积误差。
- 保护下限：**漫画可视高度不低于屏高 45%**，到线即停，不硬顶 45%/30%。
- 拖拽手柄只在面板自己范围内响应，避免与页面底部点击翻页区重叠。

### 4.4 底栏、页码、面板

- 面板出现 → **底栏隐藏**（不是上移）。
- 页码从 `BottomCenter` 上移到**面板顶部之上**，由面板高度实时驱动偏移。
- 三者由一个布局协调器统一管理，避免各自 `alignment` 打架。

### 4.5 空态

面板存在但当前页无条目时，显示引导文案「在画面上框选气泡」，不自动收起（面板不退出是已定原则）。

### 4.6 设置入口：阅读页只放功能

**阅读页不出现任何参数入口**——没有齿轮、没有长按菜单、没有“翻译设置”按钮。阅读页只保留：翻译按钮（开关）、面板、框选、条目上的点按/长按/修改。

所有参数集中在 `设置 → 翻译`：

- 设置不是独立 Activity，而是 `MainActivity` 里的 Voyager Screen（`MainActivity.kt:616` `navigator.push(SettingsScreen())`）；
- 现有 `SettingsScreen.Destination` 只有 `About(0)` / `DataAndStorage(1)` / `Tracking(2)`，新增 `Translation(3)` 并在 `when (destination)` 里加分支；
- 新建 `SettingsTranslationScreen : SearchableSettings`（照 `SettingsReaderScreen` 的 `getTitleRes()` + `getPreferences()` 写法），在 `SettingsMainScreen` 分类列表里「阅读」（约 187 行）之后插入；
- 偏好集中到新建的 `TranslationPreferences`（`PreferenceStore`，与 `ReaderPreferences` 同构，经 Metro 的 `appGraph` 取用）。

### 4.7 设置项清单

| 分组 | 项 | 说明 |
| --- | --- | --- |
| 总开关 | 启用翻译 | 关闭后阅读页不显示翻译按钮 |
| 语言 | 源语言 | 日 / 韩 / 英；决定用哪套识别字典。译文面板头部也能改，改完立刻重扫当前页 |
| | 目标语言 | 中文（简体），结构上预留多语言 |
| OCR | 语言专用模型 | 日 / 韩 / 英三个专用识别模型，各自下载、显示体积与占用；装了就优先于通用模型 |
| | 通用识别模型 | tiny / small / medium / v5-mobile 四选一，作为没有专用模型时的兜底 |
| | 下载 / 删除 / 更新 | 单文件预设下载 onnx + 字典，tar 包解包；均校验 sha256，失败可重试 |
| | 自检结果 | 通过 / 未通过 + 重新下载入口 |
| 翻译 | 引擎 | Edge（默认、免配置）/ Azure / Google / LLM |
| | 凭据 | 各引擎的 key / region / model / baseUrl（按需展开） |
| | 上下文 | 是否携带前序条目（默认开，仅 LLM 生效） |
| | 测试连接 | 单条试译，回显耗时与错误码 |
| 隐私 | 联网同意 | 明确「只发送识别文字，不发送图像」；关闭则仅 OCR 无译文 |
| 其他 | 面板默认高度 | 默认 30%（运行时可拖到 45%），记忆上次值 |
| | 清空当前会话 | 会话不落盘，此项只影响当前打开的阅读器 |

两张表要收住：引擎凭据与模型管理各自较长，用**可折叠分组**，避免设置页变成一屏几十项。

### 4.8 首次使用：按「配置完整性」跳设置

判据不是“第一次”，而是**配置是否完整**：

```
模型已下载并自检通过 && 翻译引擎可用（免配置或已填凭据） && (引擎需联网 -> 联网已同意)
```

任一不满足，点翻译按钮**直接跳设置**，不弹半成品面板。这样用户删了模型、清了 key、撤了同意，都会回到同一条正确路径。

跳转与返回：

- 现有 `Intent.ACTION_APPLICATION_PREFERENCES` 分支（`MainActivity.kt:614`）只能落到设置首页，需要新增一个 extra（如 `settingsDestination = Translation`）在 `handleIntentAction` 里解析并直达子页，否则用户落地后还要自己找两跳；
- 从 `ReaderActivity` 启动 `MainActivity` 返回时，`ReaderActivity` 只是 `stop` 而非 `destroy`，会话与面板状态仍在；
- 返回后用 `onResume` 复查配置：满足则**自动继续开启翻译**（靠一个 pending 标记）；仍不满足则保持关闭并轻提示，**不重复跳转**（否则会锁死在设置页）。

设置页要主动引导缺项：没有模型时高亮「未下载」，默认推荐 small rec，一键下载。

### 4.9 配置变更对现有会话的影响

| 变更 | 对当前会话的影响 | 处置 |
| --- | --- | --- |
| OCR 模型 / 源语言 | 识别口径改变，识别框全部作废 | 丢弃已识别框、重建识别器、**自动重扫当前页**；已翻译条目保留（文字来源未变） |
| 翻译引擎 / 凭据 | 译文来源改变 | 保留原文，现有条目标记「待重译」，提供一键重译 |
| 关闭联网同意 | 无法翻译 | 保留原文，面板显示「联网已关闭」 |
| 面板默认高度 | 仅初始值 | 不影响当前会话 |

另外：模型正在下载时返回阅读页，翻译按钮置灰并显示进度，下载完成后自动恢复可用。

## 5. 坐标系契约（核心）

### 5.1 归一化基准

**以“该页经 `processPagedImage` 处理后的显示图像素坐标系”为基准，存 0..1 的矩形。**

理由：与缩放/平移解耦（用户放大到 3 倍画的框，和缩到 0.5 倍画的框，归一化后一致）；与裁切可复现（裁切时重跑同一变换即可得到同一坐标系）。

### 5.2 三套渲染栈的映射来源

| 栈      | 视图                                                                                               | 屏幕点 → 页面像素                                                                          | 缺口                                                                                                    |
| ------ | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 经典翻页   | `ReaderPageImageView.pageView`（`ReaderPageImageView.kt:64`，private）→ `SubsamplingScaleImageView` | 库自带 `viewToSourceCoord` / `sourceToViewCoord`                                       | 需加访问器暴露 `pageView`；SSIV 的 source 坐标 = 处理后图，不是原始文件                                                     |
| 条漫     | `WebtoonStripImageView` 自绘                                                                       | `onDraw` 内 `scale = width / imageWidth`，`source = viewLocal × (imageWidth / width)` | `onTouchEvent` 直接 `return false`，触摸在外层 RecyclerView，需减去 item 的 top；离屏时 `releaseStrips()` 会释放位图（>64MB） |
| WebGpu | Compose 自绘                                                                                       | 内部 `page.x / page.y / page.scale`                                                   | 无对外 API，需新增 `viewToPagePoint()`；双页时按 `spreadPosition` 判定左/右归属                                         |

**结论**：三种栈都能实现，没有阻塞项；但必须各写一次，无法在 Activity 层统一。

### 5.3 变换链与 `cropBorders`

显示图 = 原文件 → `processPagedImage`（`splitInHalf` / `rotateDualPage` / `splitAndMerge`）→ Coil 解码（`cropBorders`）→ 视图缩放。

- 前两段是**确定性**的，可以重跑，从而与显示图对齐；
- `cropBorders` 在 Coil 解码期按像素扫描裁边，**裁掉量不对外暴露**（默认关闭，`ReaderPreferences.kt:93`），是唯一残留偏移源。

契约：翻译态若检测到 `cropBorders = true`，裁切必须复用同一裁边实现并回填偏移；实现不了就在翻译态临时关闭该选项并提示。

### 5.4 spread：存储按 page，聚合按 spread

`WebGpuViewer` 的 spread 组成是**动态推导**的：`derivedSpreadPosition()` 依赖 `isDualPageMode()`、图片宽高比 `wideAspect`、`spreadStartIndex` 登记的孤页。同一 anchor 在竖屏单页和横屏双页下搭档可能不同。

因此：

- **存储**：每个框记 `(chapterId, page.index, side, rectNormalized)`，`side` 仅宽页切分时使用；
- **聚合**：面板显示当前 spread 内含的 page 条目，按编号排序；
- **淘汰**：五页按 spread 计（用户已定“spread 算一页”）。

### 5.5 跨页框拆分

判定：框横跨 spread 中线，且两侧面积各 > 25%。

- 拆成两个子框，分别落到左/右 `page.index`，共享 `groupId`；
- 各自识别，文本按阅读方向拼接（日漫 RTL：右页在前），**合并成一条**提交翻译；
- 编辑时两半一起重译，否则语境断裂；
- **降级路径（必现）**：spread 重组后若另一半不在当前 spread，`groupId` 合并失败 → 拆成两条独立条目，各自保留文本，提示一次“转屏后跨页译文已拆分”。
- 若两侧面积不足 25%：吸附到面积大的一侧，不拆分。

### 5.6 转屏

`ReaderActivity` 未声明 `android:configChanges`（`AndroidManifest.xml:153`），转屏必然重建 Activity。

已定规则：**转屏后翻译功能复位为关闭**，框与译文全部清空，用户重新点按钮开始。

注意与 7.4 的冲突处理：转屏和“切后台被回收”都会重建 Activity，但前者要清空、后者要恢复。实现上必须在 `SavedStateHandle` 里记录**重建前的 orientation**，重建后对比：相同则恢复，不同则丢弃并复位功能开关。

## 6. 交互细则

### 6.1 绘制

- 进入绘制态：单指拖动画框，**双指缩放仍可用**，翻页点击区禁用（复用 `DisabledNavigation`）。
- 起笔位置若落在页面边缘点击区，不得触发翻页。
- 手指抬起才生成条目；拖动中显示虚线框 + 实时尺寸。
- 框太小时（换算回原图短边 < 48px）提示「框选范围太小」，不生成条目。
- 框太大时（面积 ≥ 页面显示面积 90%）提示「请分别框选气泡」，不生成条目。

### 6.2 编号

- 按绘制顺序 1、2、3…，新框追加到末尾。
- 删除中间条目后**重排为连续编号**；内部用稳定 `id`，显示序号与 `id` 分离。
- 删除时列表就地收缩动画，不做整表重排，避免用户视线跳走。

### 6.3 点按与长按

| 手势      | 行为                               |
| ------- | -------------------------------- |
| 点按条目    | 原文展开为全文 / 收起（`ready ⇄ expanded`） |
| 长按条目    | 复制译文（Toast 反馈）                   |
| 点右上角修改  | 进入 `editing`，编辑原文                |
| 点按画面上的框 | 高亮对应条目并滚动到可见                     |

原文默认**单行 + 省略号**（`maxLines = 1`），因为面板密度有限（30% 屏高约容纳 3 条）。

### 6.4 编辑与重译

- 编辑框失焦即提交；提交时按 `id` diff，**只提交变动条目**（批量一次请求）。
- 提交内容为空 → 删除该条目**并连带删除画面上的框**，编号重排（不做撤销，用户重画）。
- 编辑态**锁定面板高度**，只让面板内部滚动；`imePadding` 作用于滚动区，不作用于整个面板，避免键盘弹出时漫画再缩一次。
- 编辑中锁翻页（与绘制态共用一把锁）。

### 6.5 视觉同步（框跟随缩放）

框和编号画在 Compose 覆盖层上，而 viewer 的 transform 每帧变化（SSIV 有 fling 动画，WebGpu 自算 `page.scale/x/y`）。

已定方案：**冻结**——用户开始缩放或拖动时临时隐藏框与编号，手指离开后按新 transform 重绘一次。实现成本最低，视觉上短暂消失。

后续可升级为每帧拉取 transform，前提是两套栈都暴露实时矩阵（SSIV 有 `OnStateChangedListener`，WebGpu 需新增 API）。

### 6.6 手势优先级

绘制态下：双指 → 缩放；单指 → 画框；轻点 → 不翻页（交给面板/退出绘制）；长按 → 不弹页面菜单。

### 7.1 会话

会话对象持有于 `ReaderViewModel`（Activity 重建后存活）：

### 7.2 五页淘汰

- 以 spread 为单位，最多保留 5 个；
- 超出淘汰最久未访问的 spread，连带丢弃其条目与框；
- **不跨章节**，切章清空。

### 7.3 翻页

- `state.currentPage` 变化即“翻页”（三种形态通吃，条漫滚到下一张图也算）；
- 翻页清空**画面上的框**，面板切换为当前页的条目（无则空态）；面板本身不退出；
- 回翻时从缓存恢复该页条目与框。

### 7.4 重建与进程回收

- `SavedStateHandle` 存**文本与归一化矩形**（不含 Bitmap），Activity 重建后还原；
- “退出阅读页不保留”仍然成立，`SavedStateHandle` 只覆盖“切后台被系统回收”这一种情况。

### 7.5 转屏

见 5.6：清空 + 功能复位 + 丢弃 `SavedStateHandle` 恢复（靠 orientation 对比区分）。

## 8. OCR 层

### 8.1 运行时

- **ONNX Runtime Android**（现有 mihon 无任何 ML 依赖，需新引入）。
- 只接 `rec`（识别），**不接 `det`**。理由：人工框选已给出区域。
- 运行时进包（每 ABI 十余 MB），**“本体不自带 OCR”只指不带权重**，不是不带运行时。

### 8.2 模型预设（内建，不开放导入）

应用只维护一份**封闭预设清单**：用户只能在清单里选择下载，不能导入自带的 onnx 文件。字段沿用 `kiss-translator-dev/src/localAi/core/catalog.ts` 的结构，但**不对外暴露**，仅作内部数据：

| 字段                           | 说明                                                |
| ---------------------------- | ------------------------------------------------- |
| `id` / `name` / `version`    | 唯一标识与展示                                           |
| `task`                       | 固定 `ocr-recognition`                              |
| `languages`                  | `multilingual` / `ja` / `ko` / `en`               |
| `dir` / `base` / `files[]`   | 下载地址 = `base + "/" + path`，每文件带 `size` 与 `sha256` |
| `charset`                    | 字符表文件（CTC 解码头）                                    |
| `inputHeight` / `inputWidth` | 归一化尺寸（PP-OCR 惯例高 48）                              |
| `normalize`                  | `{ scale, mean, std, channel }`                   |
| `ctc`                        | `{ blankIndex, collapseRepeated }`                |
| `vertical`                   | 是否支持竖排                                            |

因为不再有外部导入，`normalize` / `ctc` 这类“猜错就输出乱码”的字段由我们写死，风险从运行时转移到**发版前验证**。

### 8.3 下载清单（按源语言选模型）

依据 RapidOCR 官方模型列表（<https://rapidai.github.io/RapidOCRDocs/main/model_list/>）选型，而不是继续押多语种模型：

- 日文**没有** PP-OCRv5 识别模型；官方给的是 `japan_PP-OCRv4_rec_mobile`（PP-OCRv5 的 `ch` 也含日文，PP-OCRv6 的 `tiny` 字典里没有日文）；
- 韩文、英文有 PP-OCRv5 专用模型，效果明显好于多语种；
- 多语种模型（v6）对英文够用、对日韩弱，降级为**兜底**；
- 检测（DB）与文字语种无关，一个模型通吃，不必按语言切换。

**语言专用模型**：ModelScope 上 RapidOCR 的单文件导出，权重与字典分开下载（均已实测可直连、已核 sha256）：

- **v5 mobile 只声明 `zh, en`，不能用于日/韩**；日韩靠专用模型或 v6 small/medium。
- v6 tiny 字典不含日文，预设在代码里显式声明 `zh, en, ko`，避免被当成日文兜底。
- 单文件预设下载完 onnx 还要下载字典，缺任一个都视为未就绪（`resolve()` 返回 null）。
- tar 包解包后校验 charset 非空、文件数与预设一致。
- **CTC 解码要处理空格类别**：英文/韩文字典本身不含空格符，模型在字典后追加一个空格类（总类别数 = 字典长度 + 2）；日文字典最后一行就是空格。解码时按类别数判断末尾是不是空格类，否则英文单词会连在一起。

### 8.4 下载、校验与自检

- 下载到 `filesDir/models/<id>/`，带进度、断点续传、失败重试；
- 落盘后逐文件校验 `size` + `sha256` → 解包 → 校验 charset 存在且非空；
- 首次使用前跑一次**自检**（用用户第一个框的裁切图）：输出为空、全是同一字符、或字符表外占比过高 → 判定模型损坏或不兼容，禁用该预设并提示重新下载；
- 预设清单随版本升级时，按 `version` 判定旧下载失效并提示重新下载；
- 自检只判“模型能否正常输出”，不做语言判定——语言覆盖率只用于发版前的选型评测。

### 8.5 框内分列（本方案的核心 OCR 问题）

用户框的是**整个气泡**，而识别模型一次只吃一列（竖排日文）或一行（横排）。

1. 二值化 → 投影切分（竖向统计空白列 / 横向统计空白行）；
2. 切出 1..N 段，逐段识别，按阅读顺序拼接；
3. **降级**：切分失败（描边字、彩色气泡、拟声词）→ 整框不切分直接识别；
4. 倾斜字：±5°/±10° 旋转重试一次。

### 8.6 调度

- **串行队列**，先画先出，天然产生进度感；
- 单条失败不阻断后续（跳过继续）；
- 面板关闭、翻页、删除条目时取消对应任务并丢弃结果（防止结果写到别的页）。

### 8.7 裁切

- 从 `chapterCache` 里的页图文件用 `BitmapRegionDecoder` **按区域全分辨率解码**（`HttpPageLoader.internalLoadPage` 已保证文件存在）；
- 用户缩小后画框也不糊，因为不依赖显示分辨率；
- 缓存文件可能被清理（源码里已有 `FileNotFoundException` → 重新入队的分支），复用同一降级；
- 条漫页的图可能被 `releaseStrips()` 释放，裁切走文件路径即可，不依赖内存 strips。


## 9. 翻译层

### 9.1 provider 抽象

参考 `kiss-translator-dev/src/builtin-plugins/` 的做法：**声明式预设 + 少量钩子**，而不是每个 provider 一个类。

```kotlin
interface TranslationProvider {
    val id: String
    val displayName: String
    val requiresKey: Boolean
    val maxBatch: Int              // 单次请求最多几条
    suspend fun translate(
        texts: List<String>,
        from: String?,             // null = 自动检测
        to: String,
        context: List<String>,     // 前序条目原文+译文，供 LLM 用
    ): List<String>
}
```

能力用声明表达（`supportsBatch` / `supportsContext` / `maxChars`），不要散装布尔开关。

**配置归属**：provider 的选择与凭据全部在 `设置 → 翻译`（4.7），阅读页只读取已解析好的 provider 实例，不做任何配置 UI。

### 9.2 三家接入细节

| Provider | 端点 | 鉴权 | Body | 批量 |
| --- | --- | --- | --- | --- |
| Edge（微软免费） | `edge.microsoft.com/translate/translatetext?from=&to=&isEnterpriseClient=false` | **无** | 纯字符串数组 | 原生支持 |
| Azure | `api.cognitive.microsofttranslator.com/translate?api-version=3.0&from=&to=` | `Ocp-Apim-Subscription-Key` + `Ocp-Apim-Subscription-Region` | `[{ "Text": "..." }]` | 原生支持 |
| Google（gtx） | `translate.googleapis.com/translate_a/single?client=gtx&dj=1&dt=t` | **无** | 单条 `q=` | 需自行合并 |
| Google Cloud | `translation.googleapis.com/language/translate/v2` | key | `q[]` 数组 | 原生支持 |
| LLM | OpenAI 兼容 `/chat/completions` | key | `messages` | 靠 prompt 约定 |

要点：

- **默认零配置走 Edge 端点**（无 key、天然批量），体验门槛最低；但它属前端内部端点，**稳定性无保证**，必须有失败降级。
- Google gtx 同样免 key，但**大陆基本不可直连**，仅作备选，UI 上标注可达性。
- LLM 走 JSON 数组约定 + 容错解析（容忍围栏与前后散文），并把前序条目作为上下文。

### 9.3 批量与占位符

一次请求带 N 条，用占位标记切回（`kiss-translator` 的 `placetag` 思路）：

```
请翻译以下 <sep> 分隔的文本，保持顺序，只输出译文，用 <sep> 分隔：
原文1<sep>原文2<sep>原文3
```

批量失败 → 自动降级为逐条重试；条数上限取 provider 声明值。

### 9.4 上下文

单框翻译必然出现指代断裂（他/她、省略主语）。把**本页前序条目的原文+译文**、以及**上一页最后 2 条**作为 context 传给 LLM，成本几乎为零，质量提升明显。非 LLM provider 忽略该参数。

### 9.5 缓存

内存 LRU（会话级，不落盘）：

```
key = hash(原文) + targetLang + providerId + model + promptVersion
```

目标语言或模型变更时自动失效。

### 9.6 失败降级

- 翻译失败：条目进 `failed`，显示**原文 + “翻译失败，点按重试”**，不显示空译文；
- 同一 provider 连续失败 3 次：本会话内降级到下一个可用 provider，并提示一次；
- 无网络：直接进 `failed`，不排队重试（避免用户关掉面板后还在打请求）。

### 9.7 隐私

- 首次联网翻译弹一次同意：明确“**只发送识别出的文字，不发送图像**”；
- 设置项可单独关闭联网（关闭后仅本地 OCR、无译文，面板提示“联网已关闭”）；
- 不记录、不上传原始页图。

## 11. 风险登记

### 11.1 技术风险

| 风险                  | 影响       | 缓解                                                |
| ------------------- | -------- | ------------------------------------------------- |
| 三套栈坐标映射各写一次，易漂移     | 框与图对不齐   | 统一归一化契约 + 每栈一组 golden 用例（开/关 cropBorders、单/双页、旋转） |
| `cropBorders` 偏移不可知 | 裁切错位     | 翻译态复用同实现回填；否则临时关闭并提示                              |
| WebGpu 无对外映射 API    | 双页栈无法落地  | 先做 P0 验证，拿不到就降级（固定比例缩放）                           |
| 面板密度不足（30% 约 3 条）   | 频繁滚动     | 原文单行省略 + 紧凑行高；必要时默认 35%                           |
| 预设模型版本升级后旧下载失效      | 老用户模型不可用 | 按 `version` 判定并提示重新下载；不静默降级                       |
| Edge 端点不稳定          | 默认路径失效   | 连续失败降级到 Azure/LLM；文案提示配置 key                      |
| Google 大陆不可达        | 备选失效     | 不作为默认；UI 上标注可达性                                   |
| 跳设置后的 pending 标记随进程被杀丢失 | 返回需重新点按钮 | pending 只做体验优化，不参与正确性判定（配置检查始终是真相）      |
| 模型下载期间离开设置页      | 下载中断     | 走现有 `Downloader`/WorkManager + 通知，不依赖设置页在前台           |
| 设置页承载 4 家引擎凭据，表单项膨胀 | 可用性下降    | 凭据与模型管理做成可折叠分组，默认收起                      |

### 11.2 质量风险（无法靠架构解决）

| 风险                  | 说明                      | 处置                  |
| ------------------- | ----------------------- | ------------------- |
| 英文手写体（美漫）识别率低       | 全大写、描边、字距夸张，通用 rec 先天偏弱 | **先做离线评测再定是否承诺**    |
| 韩文彩色/半透明气泡          | 二值化与投影切分易崩              | 降级整框识别 + 可编辑原文兜底    |
| 日文竖排多列              | 切分失败则整条乱序               | 投影切分 + 失败降级 + 用户可编辑 |
| PP-OCRv6 是否覆盖日竖排/韩文 | 清单只写 `multilingual`     | 实测；不足则换专用权重         |

### 11.3 已确认项

| 项 | 结论 |
| --- | --- |
| 横屏面板宽度 | 采用 `clamp(240dp, 30% 屏宽, 360dp)` |
| 翻译失败条目 | 显示原文 + 「翻译失败，点按重试」 |
| 回翻恢复提示 | 不提示，面板只显示当前页 |
| 切后台恢复后功能状态 | 保留「已开启」 |

原先的 4 项待确认至此全部关闭，设计无阻塞项。
