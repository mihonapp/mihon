# Mihon — журнал разработки пользовательского названия тайтла

**Дата обновления:** 25 октября 2026 г.
**Рабочая ветка:** `feat/custom-manga-title`
**Репозиторий:** [K14Morg/mihon](https://github.com/K14Morg/mihon/tree/feat/custom-manga-title)
**Назначение:** фиксировать реализацию, проверенные результаты и оставшиеся задачи для функции пользовательского названия манги.

## Цель и принцип работы

Добавить возможность задавать локальное пользовательское название манги независимо от оригинального названия, полученного из источника.

- Оригинальное название хранится в `manga.remote_title` и используется как резервное отображаемое имя.
- Пользовательское название хранится отдельно в `manga.user_custom_title`.
- Если пользовательское название не задано или состоит из пробелов, UI использует оригинальное.
- Пользовательское название предназначено для локального использования Mihon и не должно отправляться источнику вместо оригинального.
- Обновление метаданных из источника не должно перезаписывать пользовательское название.

## Реализовано

### Хранение и редактирование

- Добавлена nullable-колонка `user_custom_title` в таблицу `manga`.
- SQLDelight-запросы, мапперы и репозитории поддерживают чтение и сохранение пользовательского названия.
- Добавлен interactor `UpdateMangaCustomTitle`.
- Добавлен пункт **Custom title** в меню экрана манги и диалог редактирования.
- Пустое или состоящее из пробелов значение сбрасывается в `null`; исходное название остаётся доступным.
- Редактор поддерживает переносы введённого текста в одну строку и ограничение высоты поля.
- Сборка настроена для получения ARM64 APK `app-arm64-v8a-debug.apk`.

### Отображение, поиск и сортировка

- Библиотека: пользовательское название отображается в режимах удобной сетки, компактной сетки и списка.
- Экран манги: пользовательское название используется в заголовке и в действии глобального поиска; при заданном пользовательском названии дополнительно показывается оригинальное.
- Сортировка библиотеки по алфавиту учитывает пользовательское название, если оно задано.
- Поиск по библиотеке находит тайтлы как по пользовательскому, так и по оригинальному названию, включая запросы с полем `title:`.
- Определение дубликатов учитывает пользовательское название; в диалоге дубликатов отображается пользовательское название, если оно задано.
- История чтения: отображается пользовательское название, поиск работает по пользовательскому и оригинальному названиям.
- Раздел обновлений: отображение названия использует пользовательское название, если оно задано.
- Загрузки: в списке загрузок отображается пользовательское название, если оно задано.

### Резервное копирование и восстановление

- В `BackupManga` добавлено поле `customTitle` с номером protobuf `114`.
- Создание резервной копии сохраняет пользовательское название в сериализуемой модели.
- Восстановление передаёт пользовательское название в базу данных как при вставке новой манги, так и при обновлении существующей.
- При объединении восстановленных данных пользовательское название из резервной копии учитывается с сохранением уже существующего значения, если в резервной копии оно отсутствует.
- Добавлена автоматизированная проверка сериализации пользовательского названия в `BackupStreamTest`.

### Миграции базы данных

- Миграция `20.sqm` объединяет пользовательские изменения схемы: добавление `user_custom_title`, пересоздание `historyView` с колонкой `customTitle` и обновление `updatesView` для отображения пользовательского названия.
- Отдельные файлы миграций `21.sqm` и `22.sqm` удалены после объединения их изменений в `20.sqm`.
- Такое объединение предназначено для личной ветки, в которой допустимо начать работу с чистой базой данных. Если миграции уже выпущены пользователям, их историю нельзя переписывать таким способом без отдельного решения по совместимости.
